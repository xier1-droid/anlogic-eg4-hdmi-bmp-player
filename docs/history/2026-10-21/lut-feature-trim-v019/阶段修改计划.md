# v0.19.0 功能裁剪计划：去掉圆形音频可视化

状态：S1 local.1 已固定，待板测（lut19_attempt01_s5，14489 LUT，−684；Setup +0.155 / Hold +0.003 ns）。日期 2026-10-21。基线是 main 02f94ba / v0.18.0（lut18_attempt02_s3，15173 LUT）。分支为 feature/lut-feature-trim-v019。

## Context

v0.18.0 在功能不变的前提下已经降到 15173 LUT（77.4%）。S2 的结构改法在全设计上都没有稳定收益，所以这次改为去掉功能。用户决定只去掉圆形音频可视化，不碰缩放、四宫格和普通模式小 OSD。

- 这个功能原来出现在普通模式播放音乐时的右下角，场景模式本来就不显示。
- 去掉后，方案书中的加分项 5 就不再成立。

隔离实测在 diagnostics/lut_opt19/LUT_RECORD.md：

- 只把 AUDIO_VIS_ENABLE 改成 0，物理 LUT 减少 615～650，综合 LUT 减少 732，BRAM9k 从 52 降到 30。
- 这时 SD 域的路径 `u_stream/error_code → u_cache_control` 在策略 3 下是 −0.225 ns，在策略 5 下是 +0.031 ns。
- 用户决定在这条路径上加一级寄存器。

## 改动

- `top_tf_hdmi_audio.v`：`AUDIO_VIS_ENABLE = 0`。
  - audio_ring_levels 和 audio_ring_rom 被剪掉。
  - audio_ring_overlay 只剩 2 拍对齐流水，后级 OSD 的时序不变。
- `audio/fat32_pcm_stream.v`：新增寄存器输出 `error_flag`。
  - 它与 error_code 在同一拍置位、同一拍清零，每一拍都等于 `error_code!=0`，不增加延迟。
  - `sd_card_bmp.v` 的 narration_done 改用这个标志，不再对 8 位 error_code 做或运算。
- 测试台：tb_audio_stream 和 tb_batch3_equiv 都补上 `.error_flag()` 端口。
- 新增 diagnostics/lut_opt19/ 下的文件：
  - tb_error_flag：与冻结的 v0.18.0 模块逐拍 lockstep 比较，配有变异体 mut_no_flag。
  - run_error_flag.ps1。
  - run_td_ringoff.ps1：只用于隔离实测。
