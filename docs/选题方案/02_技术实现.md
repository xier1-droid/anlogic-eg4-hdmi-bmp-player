## 1. 总体架构

```
SD 卡场景包 ─SPI─> FAT32 扫描 ─┬─> BMP 解码(24/32bpp) ─> 缩放(32bit) ─> 帧加载 ─> SDRAM 四 bank
                               │                                          每像素 {R,G,B,T}
                               ├─> SND1–4 PCM 流 ─> 主音量(含 fade_mute) ─> HDMI 音频
                               │         │ sample_valid
                               └─> FONT.BIN / TEXT.BIN ─> BRAM32k
                                         v
  按键 ─> scenario_fsm ─ t_now/stage ─> hazard_layer ─> 亮度/对比度 ─> 转场 ─> OSD/字幕 ─> HDMI（音频环已于 v0.19.0 去掉）
                │                         ^ RGB + T 同一拍从 SDRAM 读出
                └─> bank 选择 / 音频段 / 文本段 / 数码管
```

**设计原则**
- FPGA 逻辑在所有村通用，每个村的差异全部放在 SD 卡的场景包里。
- 新增模块只插入现有链路，不改变原有图片轮播、缩略图、调节等功能的行为。
- 24 位普通 BMP 的 T 视为 255，此时灾害图层不生效，原功能完全兼容。

## 2. 像素格式：32bpp BMP，T 放在低 8 位

### 2.1 现状（已核实）
- **SDRAM 写入**：每像素一个 32bit 字，写入格式为 `write_data={bmp_data,8'h00}`，见 [sd_card_bmp.v:341](../../user_source/hdl_source/SD/sd_card_bmp.v#L341)。
- **显示读出**：只用 `video_read_data[31:8]`，见 [top_tf_hdmi_audio.v:359](../../user_source/hdl_source/top_tf_hdmi_audio.v#L359)。低 8 位空闲。
- **加载链路**：顶层 `SCALE_ENABLE(1)`，所有图片都要经过下面这条链，全程只有 24 位宽：
  [fat32_bmp_reader.v](../../user_source/hdl_source/SD/fat32_bmp_reader.v) → [bmp_scale_stream.v](../../user_source/hdl_source/SD/bmp_scale_stream.v) → [bmp24_decoder.v](../../user_source/hdl_source/SD/bmp24_decoder.v) → [image_scale_nearest.v](../../user_source/hdl_source/SD/image_scale_nearest.v)

### 2.2 改动
1. **打开 32bpp 支持**：`ALLOW_32` 改为 1，共 3 处：
   - `bmp_scale_stream.v:60`（解码器）
   - `fat32_bmp_reader.v:129`（preflight 表头预检）
   - `fat32_bmp_reader.v` 的 `g_fixed` 分支
2. **`bmp24_decoder` 输出 alpha**：
   - is_32 时，phase 3 锁存 A 后再输出像素，输出为 `pixel_rgba[31:0]`，格式 `{R,G,B,A}`。
   - 24 位图的 A 固定为 `8'hFF`。
3. **全链路位宽 24 → 32**：
   - `bmp_scale_stream`：`raw_rgb`、`raw_pipe_rgb`、`scaler_rgb`、`pixel_slot`
   - `image_scale_nearest`：`line[0:1919]`、`ram_pixel`、`out_rgb`，约多用 2 块 BRAM9k；`pixel_black` 输出 `{24'd0,8'hFF}`
   - `fat32_bmp_reader`：`bmp_data` 端口
   - `sd_card_bmp`：内部线网
4. **写入**：`write_data=bmp_data[31:0]`。
5. **缩略图**：与全屏图共用加载链，T 会一起写入；缩略图模式下 `hazard_layer` 旁路。

### 2.3 32 位 BMP 文件格式要求
[bmp_header_check.v](../../user_source/hdl_source/SD/bmp_header_check.v) 接受的格式：`dib_size≥40`、`planes=1`、`bitcount=32`、`compression=0`。

场景包工具固定输出：
- 40 字节 BITMAPINFOHEADER
- compression=0
- BGRA 字节序，行自下而上

> 图像软件导出的 32 位 BMP 常带 `BI_BITFIELDS`（compression=3），会被拒绝。32 位图只能由场景包工具生成。

### 2.4 T 编码
| 值 | 含义 |
|---|---|
| 0–239 | 到达时刻：`t_now ≥ T` 时该像素被灾害覆盖 |
| 240–249 | 保留 |
| 250 | 避险点，闪烁显示 |
| 251–254 | 保留 |
| 255 | 永不覆盖（普通像素，24 位图默认值） |

灾害类型由阶段决定，不按像素区分。

## 3. SD 卡场景包

### 3.1 文件清单（全部在根目录，8.3 文件名）
| 文件 | 内容 | FPGA 侧 |
|---|---|---|
| `PIC1.BMP` | 阶段 1 降雨预警：底图，T 全为 255 或标出雨区 | bank 0 |
| `PIC2.BMP` | 阶段 2 裂缝出现：T 为沿裂缝的序号 | bank 1 |
| `PIC3.BMP` | 阶段 3 滑坡/山洪：T 为扩散时刻 | bank 2 |
| `PIC4.BMP` | 阶段 4 避险撤离：T 为沿路线的序号，避险点为 250 | bank 3 |
| `SND1–4.PCM` | 各阶段旁白和音效，48kHz 单声道 s16le | 扫描器新增 4 个音频槽，替代 `BGM` 识别 |
| `FONT.BIN` | 本卡文案用到的汉字点阵，16×16 MSB 在左，每字 32 字节，最多 128 字 | 载入 BRAM32k |
| `TEXT.BIN` | 按阶段分段的文本，存字库序号 | 载入 BRAM32k |

> 现有扫描器 [fat32_volume_scanner.v](../../user_source/hdl_source/SD/fat32_volume_scanner.v) 只识别 `PIC1–4` 和 `BGM`，需要扩展。没有 `SND*` 时，回退到原来的 `BGM.PCM`，保持兼容。

### 3.2 `TEXT.BIN` 格式（v1）
```
偏移 0      : 魔数 "TX" (2B)，版本 1 (1B)，段数 N (1B)
偏移 4      : N 个段描述 {起始偏移 2B, 长度 1B, 类型 1B}
              类型：0=标题 1=滚动字幕 2=预警语 3=村名
其后         : 字符序列，每字 1B：0x00–0x7F 为 FONT.BIN 序号，
              0xF0–0xFF 为 ASCII 数字和符号的转义（复用 5×7 字库）
```
- 大小上限 4KB。
- 每个阶段对应的段号在 PC 工具里约定，`scenario_fsm` 按阶段号选段。

### 3.3 字库替换
- 现有 [osd_font_cn_16x16.v](../../user_source/hdl_source/osd/osd_font_cn_16x16.v) 只有 13 个字，用 `case` 实现，占 LUT。
- 改为读取 BRAM 字库。原有 13 个字由 PC 工具写进默认 `FONT.BIN` 的前 13 个位置，保证原有 OSD 文案不变。
- 卡上没有 `FONT.BIN` 时，保留 case 字库作为回退。M5 实测 LUT 后再决定是否删除。

## 4. 新增与修改模块

### 4.1 `scenario_fsm`（新增，约 400 LUT）
```verilog
module scenario_fsm(
  input  clk, rst,
  input  key_next, key_mode, key_speed,   // 单拍事件，来自按键路由
  input  sample_tick,                     // PCM 样本有效，已同步到 clk 域
  input  audio_running,                   // 0 时推演时钟退回帧计数
  input  frame_start,
  input  scene_ready,                     // 新卡首帧已提交（first_image_committed）
  input  transition_done,
  output reg [1:0] stage,                 // 0..3
  output reg       warn_mode,             // 0 科普  1 预警
  output reg [7:0] t_now,
  output reg [1:0] speed,                 // 0:1x 1:2x 2:4x
  output reg [1:0] alert_level,           // 0 蓝 1 黄 2 橙 3 红
  output           stage_req,             // 请求切到 stage 对应的 bank 和音频
  output           fade_mute,
  output           layer_enable
);
```
- **推演时钟**：
  - 每 `1600>>speed` 个 `sample_tick`，`t_now` 加 1，到 239 停住。1× 速度下约 8 秒走完。
  - `audio_running=0` 时改为每 2 个 `frame_start` 加 1。
- **阶段切换**：
  1. `key_next` 触发后，`fade_mute=1`，同时发出画面转场请求。
  2. 收到 `transition_done` 后，`stage`+1（取模 4），`t_now` 清零，切换到对应的 SND 段，再置 `fade_mute=0`。
- **预警等级**：随阶段自动变化，阶段 1–4 依次为蓝、黄、橙、红；预警模式固定为红。
- **预警模式**：
  - 用 `key_mode` 切换。
  - `stage` 固定为 3，`t_now` 固定为 239，SND4 循环播放，叠加红色闪烁边框和预警语段。
- **换卡**：采用复位方案，全局复位后回到 stage 0、科普模式。`scene_ready` 到来之前，`layer_enable=0`。
- **按键映射**：在 M4 中根据现有 [mode_key_control.v](../../user_source/hdl_source/SD/mode_key_control.v) 和 [switch_mode_control.v](../../user_source/hdl_source/SD/switch_mode_control.v) 的 mode 占用情况确定。原则是用拨码选一个 mode 作为"场景模式"，在这个模式下复用 key1/key2/key4，不新增引脚。
  - M4 核实结果：四个 mode 都已占用，改为 mode 0 下长按 KEY4 进入/退出场景模式；场景模式内 KEY2 下一阶段、短按 KEY4 MAN/AUTO、KEY1 留给预警模式。阶段直接取当前显示的图片，复用原有翻图请求与转场。详见[阶段计划](../山区避险课堂分阶段修改计划.md) M4 一节。

### 4.2 `hazard_layer`（新增，约 400–600 LUT，不用 DSP）
- **输入**：`{rgb[23:0], T[7:0]}`、`de/hs/vs`、`t_now`、`stage`、`alert_level`、`enable`、`frame_cnt`。
- **位置**：帧读出之后、亮度/对比度调节之前。
```
en      = enable && !thumbnail_mode
covered = (T < 240) && (T <= t_now)
front   = covered && (t_now - T < 6)
spot    = (T == 250)
out = !en            ? rgb
    : front          ? (blink_fast ? FRONT_COLOR[stage] : mix(rgb, HAZ_COLOR[stage], 3/4))
    : covered        ? mix(rgb, HAZ_COLOR[stage], α[stage])      // α ∈ {1/2, 3/4}，移位加法
    : spot           ? (blink_slow ? 24'h00FF00 : rgb)
    :                  rgb
```
- **配色**：
  | 阶段 | 灾害色 | α | 前沿色 |
  |---|---|---|---|
  | 1 | 不着色 | — | — |
  | 2 | 深褐 | 3/4 | 亮黄 |
  | 3 | 蓝 | 1/2 | 白 |
  | 4 | 绿 | 3/4 | 亮绿 |
- **闪烁**：由 `frame_cnt` 分频得到。前沿闪烁频率随 `alert_level` 提高，从 2Hz 到 8Hz。
- **时序**：流水 2 级，`de/hs/vs` 同步延迟 2 拍，复用 [video_delay.v](../../user_source/hdl_source/SD/video_delay.v)。

### 4.3 `pcm_master_volume`（修改，约 20 LUT）
- 新增输入 `fade_mute`：
  - 为 1 时 `target=0`；为 0 时恢复为音量档位对应的目标值。
  - 淡入淡出时斜坡步长改为 14，约 4700 个样本、约 100ms；普通调音量仍为 256。
- 文件：[pcm_master_volume.v](../../user_source/hdl_source/adjust/pcm_master_volume.v)。
- 画面转场与音频淡入淡出同时触发，见 [video_transition_control.v](../../user_source/hdl_source/video_transition_control.v)。

### 4.4 扫描器与文件加载（修改）
- **`fat32_volume_scanner`**：新增识别 `SND1–4`、`FONT`、`TEXT`，记录各文件的起始簇和大小。
- **音频**：`fat32_pcm_stream` 按 `stage` 选择对应的 SND 槽开始播放。
- **新增 `bin_to_bram_loader`**：
  - 复用 `fat32_file_streamer` 的字节流，按字节地址写入 BRAM32k。
  - 只在扫描完成后加载一次，不参与阶段切换。

### 4.5 OSD 文案（修改，约 300 LUT）
- **标题和字幕**：`status_osd_overlay` / `scroll_text_overlay` 的字符来源改为 TEXT.BIN 段，点阵来源改为 FONT.BIN。
- **预警红框**：画面四周 8px 边框，红色闪烁，只在预警模式下显示。
- **数码管**：显示阶段号（1–4）或"A"（预警），复用 `seg7_panel`。
- **推演速度**：接入 `adjust_osd_overlay` 参数条，新增一个调节项。

## 5. PC 场景包工具 `tools/make_scene_pack.py`
- **输入** `scene.yaml`：
  - 底图
  - 每个阶段的 T 来源：手绘灰度 PNG，或者折线/种子加自动生成
  - 避险点坐标
  - 各阶段音频
  - 文案
- **T 生成**：
  - 优先用手绘灰度图：越黑越早到达，直接量化到 0–239。
  - 辅助功能：
    - 折线：沿线累计长度，线宽 3–5px。
    - 种子：做距离变换；有 DEM 时按高差加权。
  - 未覆盖的像素填 255，避险点填 250。
- **输出**：
  - SD 卡文件：`PIC1–4.BMP`、`SND1–4.PCM`、`FONT.BIN`、`TEXT.BIN`
  - 对照素材：每个阶段在 `t=0/120/239` 时的 expected PNG，算法与 §4.2 完全一致，用作仿真对照的标准答案
- **复用**：音频转换复用 [tools/make_audio_corpus.py](../../tools/make_audio_corpus.py)。
- **依赖**：Python 3、Pillow、numpy、PyYAML、ffmpeg。运行时用 `py -I`。
- **示例**：先做虚构的示意村 `tools/scenes/demo_village/`，避开地图版权问题。

## 6. 资源预算

| 项 | LUT | BRAM | DSP |
|---|---|---|---|
| 32bpp 解码 + 缩放链路 32 位 | 100–200 | 9k +2 | 0 |
| hazard_layer | 400–600 | 0 | 0 |
| scenario_fsm | ~400 | 0 | 0 |
| fade_mute | ~20 | 0 | 0 |
| 扫描器扩展 SND/FONT/TEXT + bin 加载器 | ~250 | 32k +2 | 0 |
| OSD 文案、预警框、速度项 | ~300 | 0 | 0 |
| **合计** | **约 1.5–1.8k** | 9k 56/64，32k 2/16 | 13/29 |

- **目标**：LUT ≤ 85%（约 16660），Setup/Hold 裕量为正。
- **超出时**：先删除 case 字库，再执行 HANDOFF 中的 S3 批 8–11。

## 7. 验证策略
- **仿真**：
  - 测试台放在 `diagnostics/mountain_scene/`，沿用项目里 `.sv` 测试台加 ModelSim 的方式。
  - 像素类结果与 PC 生成的 expected 逐像素比对。
- **回归**：每个里程碑都要跑受影响的已有测试台，包括 BMP 解码、缩放、四 bank、PCM、`tb_pcm_preview_rescan`。
- **构建**：`diagnostics/run_td_build.ps1`，检查实际资源和时序报告。
- **板测**：每个里程碑出 `local` 候选，由用户上板确认后建 `board` 标签，遵守 [执行规则.md](../../执行规则.md)。

## 8. 后续计划（不在 v0.17.0 范围）
- 免复位换卡：重扫时同时复位 SD 协议层。
- FPGA 片上生成 T：卡上只放种子 mask，加载时做两遍 chamfer 距离变换，在 SDRAM 上读改写。
- "你往哪跑？"答题模式、适老化（大字、高对比、方言）、标记点保存到 Flash、卡损坏时的失效安全画面。

## 9. 已定决策汇总
| 决策 | 结论 |
|---|---|
| T 的存放位置 | SDRAM 像素低 8 位，用 32bpp BMP 一次写入 |
| 缩放链路 | 扩到 32 位，缩略图模式下旁路灾害图层 |
| 音频 | SND1–4 四槽，没有时回退到 BGM |
| hazard_layer 位置 | 亮度/对比度调节之前 |
| 字库和文本 | 放在卡上（FONT.BIN/TEXT.BIN → BRAM32k） |
| 换卡 | 第一版换卡后复位 |
| 音频淡入淡出 | 并入 pcm_master_volume（fade_mute） |
| T 计算 | v0.17.0 由 PC 离线完成，支持手绘；片上生成放到后续 |

## 10. 合规性说明（待官方答复）
- **赛题原文**："所有算法、控制逻辑及数据处理流程应在 FPGA 中自主编程实现……不得带有额外处理器（无论用于辅助控制还是算法预处理）"。
- **立场**：PC 工具只做离线内容制作，运行时不参与，和准备 BMP、转换 WAV 性质相同。T 图定位为"本村灾害预案数据"，可以手绘；蔓延判定、混合、时间轴、转场、OSD 全部由 FPGA 实时完成；演示时不接 PC。
- **官方答复**：待补（用户询问后记录在这里）。如果答复认为离线计算 T 不合规，就把 §8 的"片上生成 T"提前到 v0.17.0。
