## M1 32bpp 像素通路

**目标**：32 位 BMP 的 alpha 作为 T 写入 SDRAM 低 8 位；24 位图的低 8 位写 FF；原有全部功能不退化。显示链路暂不使用 T。

**所需技术**
- BMP 32bpp 格式：BGRA、40 字节头、compression=0
- Verilog 参数化位宽扩展
- 行缓存 BRAM 推断

**改动文件**（详见技术文档 §2.2）
- [bmp24_decoder.v](../../user_source/hdl_source/SD/bmp24_decoder.v)：phase 3 锁存 A，输出 32 位
- [bmp_scale_stream.v](../../user_source/hdl_source/SD/bmp_scale_stream.v)：`ALLOW_32=1`，内部改为 32 位
- [image_scale_nearest.v](../../user_source/hdl_source/SD/image_scale_nearest.v)：行缓存和输出改为 32 位；黑边输出 `{24'd0,8'hFF}`
- [fat32_bmp_reader.v](../../user_source/hdl_source/SD/fat32_bmp_reader.v)：preflight 和 g_fixed 的 `ALLOW_32=1`，`bmp_data` 改为 32 位
- [sd_card_bmp.v](../../user_source/hdl_source/SD/sd_card_bmp.v)：`write_data=bmp_data`

**步骤**
1. 阅读上述文件和 `diagnostics/bmp_decoder`、`diagnostics/image_scaling` 下的现有测试台。
2. 先改 decoder，用现有解码测试台验证 24 位图不变；再新增 32 位用例：检查 A 字节，以及行对齐（宽度×4 不需要填充）。
3. 扩展缩放链路位宽。验证 1:1、缩小、放大三种情况下，T 与 RGB 同坐标对齐。
4. 写一个 32 位测试 BMP 生成脚本（可以先简单写在 `diagnostics/mountain_scene/`，M2 再正式化）。
5. 回归：BMP 解码、缩放、缩略图、四 bank、`tb_pcm_preview_rescan`。
6. TD 构建：检查 BRAM9k 是否只增加约 2 块、LUT 增量和时序。
7. 形成 `v0.17.0-m1-local.1` 候选。板测清单：
   - 原 PIC1–4 轮播、缩略图、转场、调节、音频全部正常
   - 32 位 BMP 能正常显示（颜色正确，没有错位）

**验收**：24 位功能逐项不变；32 位图正确显示；仿真确认 SDRAM 写入数据的低 8 位等于 A。

**会话启动提示**
```
请阅读 执行规则.md、HANDOFF.md、docs/选题方案/02_技术实现.md（§2）、docs/选题方案/03_实现里程碑.md（M1）。
执行 M1：把 BMP 加载链路扩展为 32 位，32bpp BMP 的 alpha 作为 T 写入 SDRAM 像素低 8 位，
24bpp 图低 8 位写 FF。先仿真（新测试台放 diagnostics/mountain_scene/），跑受影响回归，
再 TD 构建，形成 v0.17.0-m1-local.1 候选并给出板测清单。不实现显示侧 hazard_layer。
```

## M2 场景包工具（图像部分）

**目标**：PC 工具生成示意村的 PIC1–4（32bpp）和 expected PNG。音频和字库放到 M4、M5 再接入。

**所需技术**
- Python：Pillow、numpy、PyYAML
- 距离变换：`scipy.ndimage.distance_transform_edt`，或自己实现两遍 chamfer
- 折线逐像素累计长度
- 手写 BMP 文件头

**步骤**
1. 定义 `scene.yaml` 结构：底图；每个阶段的 T 来源（手绘 png / 折线 / 种子）；避险点；输出目录。
2. 实现 T 生成：
   - 手绘灰度图量化到 0–239
   - 折线累计长度
   - 种子距离变换
   - 未覆盖像素填 255，避险点填 250
3. 实现 32 位 BMP 写出：40 字节头、compression=0、BGRA、自下而上；再写一个反向读取自检，确认 `bmp_header_check` 的 4 个条件都满足。
4. 实现 `hazard_layer` 的 Python 参考模型（与技术文档 §4.2 逐位一致：配色、α 移位、前沿宽 6），输出 `t=0/120/239` 以及闪烁亮、暗两相的 expected PNG。
5. 制作示意村 `tools/scenes/demo_village/`：画一张简化山区底图，带沟谷、坡体、村庄、高地；画裂缝线和撤离路线。
6. 编写使用说明 `tools/scenes/README.md`。

**验收**：生成的 BMP 能被 M1 板子正确显示；参考模型的输出符合预期，这一项由用户目视确认。

**会话启动提示**
```
请阅读 执行规则.md、docs/选题方案/02_技术实现.md（§2.3、§2.4、§4.2、§5）、03_实现里程碑.md（M2）。
执行 M2：编写 tools/make_scene_pack.py（图像部分），按 scene.yaml 生成 32bpp BMP（40 字节头、
compression=0、alpha=T）、hazard_layer 的 Python 参考模型和 expected PNG，制作示意村
tools/scenes/demo_village/。Python 用 py -I 运行。不改 RTL。
```

## M3 hazard_layer 灾害图层

**目标**：显示链路按 T 和 t 实时合成灾害图层。这一步 t 由按键手动步进，或自动匀速增加，不依赖 FSM 和音频。

**所需技术**
- 视频流水线：`de/hs/vs` 对齐
- 移位加法 alpha 混合
- 帧计数分频闪烁
- 跨时钟域：t 来自控制域时需要同步

**步骤**
1. 新建 `user_source/hdl_source/scene/hazard_layer.v`，按技术文档 §4.2 实现，2 级流水。
2. 接入 [top_tf_hdmi_audio.v](../../user_source/hdl_source/top_tf_hdmi_audio.v)：使用 `video_read_data[7:0]`，插在亮度/对比度调节之前；缩略图模式下旁路。
3. 临时测试源：stage 由当前图片序号决定；t 每 2 帧加 1，循环。后续会被 M4 的 FSM 替代，用宏或参数隔离。
4. 测试台：
   - 输入 M2 的 BMP 像素序列，逐像素比对 expected PNG，覆盖 3 个时刻和闪烁两相
   - 检查同步信号的延迟一致
5. 回归和 TD 构建：关注显示时钟域的时序。
6. 用示意村卡生成 `v0.17.0-m3-local.1`。板测：裂缝、洪水、路线是否在循环蔓延；避险点是否闪烁；24 位普通图有没有被染色。

**会话启动提示**
```
请阅读 执行规则.md、HANDOFF.md、02_技术实现.md（§2.4、§4.2）、03_实现里程碑.md（M3），
以及 M2 的参考模型 tools/make_scene_pack.py。执行 M3：实现 hazard_layer.v 并插入显示链路
（亮度/对比度之前、缩略图旁路），先用临时自增 t 测试；测试台与 Python expected 逐像素比对；
回归、TD 构建，形成 v0.17.0-m3-local.1。
```

## M4 scenario_fsm、SND1–4 与音画同步转场

**目标**：按键依次推进 4 个阶段，每个阶段切换对应的图和音频；t 由音频样本驱动；切换时画面和音频同时淡入淡出。

**所需技术**
- FAT32 目录项匹配扩展
- 多文件音频切换
- 增益斜坡
- 状态机
- 跨时钟域单拍事件同步：音频样本 tick 送到控制域

**步骤**
1. 核实按键、拨码 mode 的现有占用（[mode_key_control.v](../../user_source/hdl_source/SD/mode_key_control.v)、[switch_mode_control.v](../../user_source/hdl_source/SD/switch_mode_control.v)），确定"场景模式"的入口和按键映射，写进阶段计划。
2. [fat32_volume_scanner.v](../../user_source/hdl_source/SD/fat32_volume_scanner.v)：新增 SND1–4 槽；没有 SND 时回退到 BGM。
3. 音频流模块 `audio/fat32_pcm_stream.v` 按 stage 选择槽；`pcm_master_volume` 新增 `fade_mute`，见技术文档 §4.3。
4. 新建 `scene/scenario_fsm.v`（§4.1），替换 M3 的临时 t；连接 `transition_done`、`first_image_committed`、`sample_valid`。
5. M2 工具补上音频输出：调用 `make_audio_corpus.py` 生成 SND1–4，并为示意村准备旁白，可以先用 TTS 或占位音效。
6. 测试台：
   - fsm 按键序列
   - 音频缺失时回退到帧计数
   - fade 增益单调、没有跳变
   - 扫描器识别 SND 槽
   - 并回归 `tb_pcm_preview_rescan`
7. 生成 `v0.17.0-m4-local.1`。板测：4 个阶段完整走一遍；转场没有爆音；旁白关键词与淹没时刻对得上；速度切换生效；原图片模式不退化。

**会话启动提示**
```
请阅读 执行规则.md、HANDOFF.md、02_技术实现.md（§3.1、§4.1、§4.3、§4.4）、03_实现里程碑.md（M4）。
执行 M4：先核实按键/拨码 mode 占用并确定场景模式入口；扩展扫描器识别 SND1–4（无则回退 BGM）、
音频按阶段切换、pcm_master_volume 加 fade_mute；实现 scenario_fsm 替换 M3 临时 t；
M2 工具补充音频输出。仿真、回归、TD 构建，形成 v0.17.0-m4-local.1。
```

## M5 卡上字库文本、OSD 文案与预警模式

**目标**：从卡上读取 FONT.BIN/TEXT.BIN 显示本村文案；实现预警模式（红框、预警语、SND4 循环）；推演速度接入参数条；数码管显示阶段号。

**所需技术**
- 文件到 BRAM 的加载器
- BRAM 字库查表的时序：地址提前一拍
- 自定义二进制格式（TEXT.BIN v1，见技术文档 §3.2）
- OSD 字符渲染改造

**步骤**
1. 扫描器新增 FONT、TEXT；新建 `scene/bin_to_bram_loader.v`，复用 `fat32_file_streamer` 的字节流。
2. 改造中文 OSD：点阵从 BRAM 读取，注意读延迟，渲染流水要提前一拍；没有 FONT.BIN 时回退到 case 字库。
3. `status_osd_overlay` / `scroll_text_overlay` 的字符源改为 TEXT 段，由 scenario_fsm 的 stage 和 warn_mode 选择段。
4. 预警模式：红框闪烁、预警语、SND4 循环、数码管显示"A"。
5. `adjust_osd_overlay` 新增"推演速度"调节项。
6. M2 工具补上 FONT.BIN/TEXT.BIN 生成：自动统计文案用到的汉字，用 SimSun 16px 渲染，与现有字库的风格一致；原有 13 个字放在前面。
7. 测试台：TEXT.BIN 解析、BRAM 字库渲染比对、模式切换。TD 构建后**根据 LUT 决定是否删除 case 字库**。
8. 生成 `v0.17.0-m5-local.1`。板测：各阶段文案正确；预警模式完整；没有 FONT/TEXT 文件的旧卡仍然正常。

**会话启动提示**

执行 M5：扫描器识别 FONT/TEXT 并载入 BRAM32k；中文 OSD 改为 BRAM 字库（无文件回退 case 字库）；

## 风险与应对
| 风险 | 出现阶段 | 应对 |
|---|---|---|
| 缩放链路扩位后，BRAM 或时序紧张 | M1 | 行缓存只扩 T 的 8 位，单独用一块 RAM；或者按关键路径加寄存器切分 |
| 显示域增加流水后，Hold 和 Setup 出问题 | M3 | 按项目里"路径等价寄存"的经验处理 |
| 切换音频文件时间过长，淡入后仍然静音 | M4 | fade 等待"新文件首个样本"后再淡入 |
| BRAM 字库的读延迟导致字符错位 | M5 | 对照现有 OSD 流水，地址提前一拍 |
| LUT 超过 85% | M4/M5 | 删除 case 字库，执行 HANDOFF 中的 S3 批 8–11 |
| 官方认定离线计算 T 不合规 | 任意时刻 | 把"片上生成 T"插到 M5 之后，作为 M5.5 |
