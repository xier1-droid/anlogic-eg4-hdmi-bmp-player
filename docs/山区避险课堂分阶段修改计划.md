# v0.17.0 山区防灾避险课堂分阶段修改计划

状态（2026-10-15）：M0 计划与基线完成，标签 v0.17.0-plan.1；M2 场景包工具（图像部分）本地完成并阶段提交（纯 PC 工具，无标签），待用户目视确认 expected 和 M1 板上显示；M1 在另一会话中进行。基线 main 1818adc / v0.16.0，分支 feature/mountain-escape-classroom。

## Context

v0.16.0 已发布（main 1818adc）：14190/19600 LUT（72.4%）、8250 寄存器、BRAM9k 54/64、BRAM32k 0/16、DSP 13/29，Setup +0.144ns、Hold +0.003ns。v0.17.0 在现有图片轮播、缩略图、转场、调节、音频全部保留的前提下，加入"山区防灾避险课堂"：SD 卡场景包中的 32bpp BMP 携带每像素到达时刻 T，FPGA 按推演时间 t 实时合成灾害图层，配合分阶段旁白、音画同步转场、卡上字库文案和预警模式。

设计依据：[方案书](选题方案/01_方案书.md)、[技术实现 v1.0](选题方案/02_技术实现.md)、[实现里程碑](选题方案/03_实现里程碑.md)。本文件是执行规则要求的阶段计划，记录范围、基线、回退、各里程碑验收方式和标签；技术细节以技术实现文档为准，不在此重复。

## 范围

- **做**：32bpp 像素通路（T 写入 SDRAM 像素低 8 位）、PC 场景包工具、`hazard_layer`、`scenario_fsm`、SND1–4 分阶段音频与 `fade_mute`、FONT.BIN/TEXT.BIN 卡上字库文本、预警模式、推演速度参数项、数码管阶段号。
- **兼容**：24 位普通 BMP 的 T 视为 255，灾害图层不生效；卡上没有 SND/FONT/TEXT 时分别回退到 BGM 和 case 字库；缩略图模式旁路灾害图层。原有用户可见功能逐项不退化。
- **不做**（技术实现 §8）：免复位换卡、片上生成 T、答题模式、适老化、Flash 保存标记点、卡损坏失效安全画面。若官方认定离线计算 T 不合规，按里程碑风险表把"片上生成 T"插入为 M5.5，另行补充计划。
- 不改时钟、引脚和约束；不新增引脚，场景模式复用拨码与 key1/key2/key4（具体映射在 M4 核实后写回本文件）。

## 每个硬件里程碑的通用门槛

1. 先跑直接相关专项测试，再跑受影响回归（至少 BMP 解码、缩放、缩略图、四 bank、PCM、`tb_pcm_preview_rescan`，后者需与 `tb_pcm_production` 同批编译）。
2. 完整 TD 构建（`diagnostics/run_td_build.ps1`），检查实际资源与时序报告；LUT 下降或上升都可能暴露新关键路径，按路径等价寄存处理。
3. 固定 `releases/v0.17.0/mN-local.K/`（bit、BOARD_VALIDATION、MANIFEST、必要报告），建 local 标签交板测。
4. 用户确认后记录 BOARD_RESULT，建 board 标签并推送分支与本阶段标签；失败则定点修复生成 local.K+1，失败候选保留不建 board。
5. 只记录用户实际反馈；整体反馈按整体记录，不补造单项结果。

### M1 32bpp 像素通路

- 改动：`bmp24_decoder`（phase 3 锁存 A，输出 `{R,G,B,A}`，24 位图 A=FF）、`bmp_scale_stream` / `fat32_bmp_reader` 的 `ALLOW_32=1`（共 3 处）、缩放链路与 `bmp_data` 扩到 32 位、黑边 `{24'd0,8'hFF}`、`sd_card_bmp` 写入 `write_data=bmp_data`。显示链路暂不使用 T。（`bmp_read.v` 在工程文件中但未被实例化，不在生产链路上。）
- 仿真验收：24 位解码输出与改前一致；32 位用例检查 A 字节和无填充行对齐；1:1、缩小、放大三种情况下 T 与 RGB 同坐标；SDRAM 写入数据低 8 位等于 A。
- 构建验收：BRAM9k 约 +2，LUT 增量与时序在报告中核实。
- 板测：原 PIC1–4 轮播、缩略图、转场、调节、音频全部正常；32 位 BMP 颜色正确、无错位。

### M2 场景包工具（图像部分）

- 产出：`tools/make_scene_pack.py`、`scene.yaml` 结构、示意村 `tools/scenes/demo_village/`、`tools/scenes/README.md`。
- 验收：生成的 BMP 通过反向读取自检（`bmp_header_check` 4 个条件：dib≥40、planes=1、bitcount=32、compression=0）；`hazard_layer` Python 参考模型与技术实现 §4.2 逐位一致，输出 t=0/120/239 及闪烁两相 expected PNG，由用户目视确认；BMP 能被 M1 板子正确显示。
- Python 用 `py -I` 运行；不改 RTL。
- **本地结果（2026-10-15）**：
  - 工具：`tools/make_scene_pack.py`，T 来源支持 paint、polyline、seeds（8 邻域测地距离，可选 mask、DEM 限高和上坡代价，不依赖 scipy），避险点固定为 250。
  - 示意村：`tools/scenes/demo_village/` 下有 scene.yaml、底图生成脚本、base/dem/gully_flood.png。说明见 `tools/scenes/README.md`。
  - 4 张 BMP：每张 1228854 字节（640×480×4+54），读回自检全部通过；Pillow 独立读取的 RGB 与底图逐像素一致。
  - 参考模型：与按 §4.2 逐行转写的逐像素标量实现比对，覆盖 4 个阶段、9 个 t 值、闪烁 4 种组合、T 取遍 0–255，共 221184 个像素，0 处不一致。
  - 自检拦截：把表头改成 compression=3、bitcount=24、dib=12、planes=2，四种情况都会报错。
  - 可复现：重复生成，BMP 和 PNG 文件大小相同，逐字节比较一致。
- **M2 定下的细节**（技术文档只写了颜色名称和频率范围；M3 RTL 以 README 为准）：
  - 灾害色：深褐 603818、蓝 2060FF、绿 20C040。
  - 前沿色：亮黄 FFE000、白 FFFFFF、亮绿 40FF40。
  - blink_fast 取 frame_cnt 的第 4/4/3/2 位（随 alert_level），blink_slow 取第 5 位。
  - 阶段 1：covered/front 保持原色，避险点仍然闪烁。
- **示意村阶段 3 的调整**：只画山洪（支沟手绘 + 主河种子扩散），不画滑坡体，因为阶段 3 统一染蓝色。
- **尚未验证**：用户目视确认 expected；M1 候选板上显示这 4 张 BMP。生成物在 `out/`，不入库。

## 风险

| 风险 | 阶段 | 应对 |
|---|---|---|
| 缩放链路扩位后 BRAM 或时序紧张 | M1 | 行缓存只为 T 单独加一块 8 位 RAM；或按关键路径加寄存器 |
| 显示域加流水后 Setup/Hold 出问题 | M3 | 路径等价寄存；Hold 基线余量仅 3ps，每次构建复核 |
| 切换音频文件耗时，淡入后仍静音 | M4 | fade 等待新文件首个样本再淡入 |
| BRAM 字库读延迟导致字符错位 | M5 | 对照现有 OSD 流水，地址提前一拍 |
| LUT 超过 85% | M4/M5 | 删 case 字库，再做 S3 批 8–11 |
| 官方认定离线计算 T 不合规 | 任意 | 插入 M5.5 片上生成 T |
